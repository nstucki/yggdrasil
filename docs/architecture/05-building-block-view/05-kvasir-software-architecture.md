# 5.1.4 Blackbox `kvasir-software-architecture` (dual-mode)

_Part of [Architecture Workflow (Yggdrasil) — Architecture (arc42)](../README.md) · [§5](README.md)._

- **Purpose:** author the arc42 architecture Workfile in either mode with the same ADR discipline — structure and contracts are Kvasir's judgment; the document's shape (twelve sections, their subsections, the appendices) and the target's mechanical facts (shape, scope, `next-adr`) are given, not derived.
- **Provided interface (R5 — supersedes the R2 "fill the scaffold" form):** brief lines `Mode: document-existing | decide-new` (absent ⇒ `decide-new`), the scaffold step's `Scaffold result:` line (I-5), and the Workfile path to **create** (`NN-architecture-arc42.md`; an existing file at that path → ask, never overwrite). Kvasir writes the header itself from the result line — `Status: Proposed`, `Date`, `Document scope` (= `document-scope`), `Mode … (source …)` (from the brief), `Scaffold: <target> (structure: created | verified | extended)`, `Existing document: <path> (<shape>)` iff update delta, `Section scope:` (its own verdict) — then §1–§12 with every subsection heading from the **Document shape table** the skill now carries (section and subsection numbers and titles, appendix headings; Yggdrasil-authored, no arc42 guidance text), Appendices A–C by mode, and **Appendix D — Layout Map** (ADR-0019). **No template skill is loaded and no arc42 guidance text is present at any point** — the "Filling the scaffold" rules and the attribution iff-rule collapse to: never delete or renumber a heading; mark rather than drop; the document never contains licensed guidance, so it never carries the notice (the `Focus: document` iff-check remains as a safety net). The repository look-up rule is unchanged from R2: read the shape report, and in update-delta scope read the existing document's index, `01-`, `04-`, `05-`, `09-` sections and whatever this objective touches — whether those are files (flat legacy) or folders (5.1.13). **Split rule (Appendix D):** default one topic document per section, named `01-<section-slug>.md`; split only when the section holds **three or more** units of its natural grain that a reader would consult independently and each is more than a short paragraph — §5: the whitebox overview plus one document per building-block group a reader navigates to separately (a subsystem, a Level-2 whitebox, a family of related blackboxes); §6: one per scenario; §8: one per concept; §10: overview vs. scenarios; §9: always one record per decision (fixed); §1, §2, §3, §4, §7, §11, §12: one document unless the grain rule clearly applies. **Three row patterns, no others:** (i) topic documents — `NN-<section>/NN-<slug>.md`, promotion `depth − 1`; (ii) decision records — `09-architecture-decisions/NNNN-<slug>.md`, promotion 2; (iii) **the `## 9. Architecture Decisions` heading itself** — target `09-architecture-decisions/README.md`, promotion `—`, because that heading's body is the decision log, which lands in §9's *generated index* by row-append rather than becoming a topic document; it is a named exception to the path and promotion formulas, not an omission from them. **A topic document is exactly one Workfile heading plus its descendants that have no row of their own** — so a parent's own body (e.g. `### 5.1`'s intro, diagram, and block table) can be one document while its children (`#### 5.1.n`) are carved out into theirs; sibling headings are never grouped into one document (two roots would mean two H1s). Every heading below a section heading is therefore covered exactly once — by its own row or by its nearest mapped ancestor; in a **split** section, a subsection carrying only an omission marker is listed in the map as `→ index (omitted)` and gets no document (in a single-document section the marker simply travels inside the document). Behavior by mode:
  - `decide-new`: unchanged (Workflow steps 1–11, Appendices A–C, `Package check:`).
  - `document-existing`: inputs = reviewed **architecture-context** Workfile (`NN-context-architecture-<system>.md`, system-scoped — R4) + optional user focus; §1.1 states the documented scope, §1.2 quality goals *inferred from evidence* and marked so; section scope defaults to all twelve, each filled from cited evidence or marked `_Omitted — no evidence in context Workfile_`; §5/§6/§8 describe what exists, every block citing a path from the context Workfile; Appendix A records **existing** decisions inferable from evidence as ADRs with an extra line `- **Kind:** as-is (inferred from <paths>)`, still `Status: Proposed` (the *description* is what is proposed; promotion on persistence unchanged); Appendices B and C carry the marker `_Not applicable — document-existing mode_`; no `Package check:`; the report's item 3 reads `Package check: n/a`. Boundary added: "never propose a change in document-existing mode — an improvement idea goes to §11 as technical debt, not to §4/§9."
  - Update-delta applies to both modes (document mode over an existing arc42 directory is a refresh delta).
