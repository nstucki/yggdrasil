# 4. Solution Strategy

_Part of [Architecture Workflow (Yggdrasil) — Architecture (arc42)](README.md)._

- **One packaged workflow skill, `odin-architecture-workflow`, in a new dedicated feature directory `skills/architecture/`** alongside the relocated specialists `kvasir-software-architecture`, `brokk-architecture-persistence`, `mimir-codebase-context`, the relocated-and-renamed `brokk-arc42-template` (formerly `kvasir-arc42-template`), and the new `heimdall-architecture-review` (ADR-0009 as extended, ADR-0011; user-directed). The directory is registered as mandatory in `setup.sh` and `validate.sh`; every skill reference stays load-by-name, so nothing else changes (C-11). *Tactic for Reusability and Doctrine Minimization:* architecture doctrine lives outside the engineering workflow's directory, mirroring the "one workflow skill + its specialists per feature directory" convention. *Tactic for Backward Compatibility:* engineering-trigger text unchanged (ADR-0002); relocated skills keep their slugs (except the renamed template, which the engineering skill will no longer reference), so `odin-engineering-workflow`'s load-by-name references to the architecture specialists keep resolving. *R4:* `mimir-codebase-context` is replaced by `mimir-architecture-context` (here) and `mimir-engineering-context` (in `engineering/`), so `architecture/` still holds six skills and `engineering/` grows to five (ADR-0012).
- **Scaffold before decide** — a Brokk session loading `brokk-arc42-template` instantiates the arc42 skeleton into the architecture Workfile (header pre-filled, existing-document shape and next ADR number detected, all twelve headings with guidance, mode-driven appendix treatment, attribution notice placed) as a dedicated step before Kvasir drafts; Kvasir fills the scaffold and no longer loads any template skill (ADR-0011, user-directed). *Tactic for Doctrine Minimization:* the skeleton and its instantiation mechanics have one owner (Brokk); Kvasir's skill shrinks to judgment. *Cost consequence:* +1 Brokk dispatch and +1 standing review per invocation (C-12, Q-3, Q-5).
- **Mode is a first-class control line** — `Mode: document-existing | decide-new` — set by direction or inference, recorded in the shape verdict, echoed in every specialist brief, in the Workfile header, and in the Response. *Tactic for Clarity of Intent* (ADR-0001, §8.1, Q-7).
- **`kvasir-software-architecture` becomes dual-mode** by a `Mode:` brief line branching Workflow steps 1, 3, 4–5, 10 and the Output Contract; the scaffolded skeleton, ADR format, and `Status: Proposed` discipline are shared by both modes (ADR-0001, ADR-0011). A **dedicated `heimdall-architecture-review` skill** owns the scaffold checklist (`Focus: scaffold`), the architecture-document checklists (both modes, selected by its own `Mode:` line), and the persisted-directory checklist (`Focus: persistence`); `heimdall-engineering-review` drops its `Focus: architecture` section and delegates its persisted-architecture checks to the new skill by name (ADR-0010, user-directed). *Tactic for Doctrine Minimization and Backward Compatibility:* extend Kvasir in place, absent `Mode:` = today's behavior (Q-6); every architecture checklist exists exactly once, in the architecture skill.
- **Composition by skill load with an explicit caller contract** — the engineering workflow does not re-describe the architecture steps; it loads `odin-architecture-workflow` and executes it as a sub-procedure with a one-line caller contract and receives a one-line return block (ADR-0003). The contract carries no context Workfile: each workflow gathers its own purpose-scoped context (ADR-0014, superseding ADR-0004). *Tactic for Doctrine Minimization and Reusability:* I-1/I-3 are the only coupling surface, identical for both paths (§8.2, Q-1, Q-2, Q-4).
- **Review gate and persistence move into the workflow**; engineering step 5 is removed and steps renumbered; engineering step 9 delegates persistence to the Architecture workflow's persistence step (ADR-0005). Decide-mode persistence is inline standalone, deferred inside a composite (ADR-0006). *Tactic for Backward Compatibility:* engineering dispatch sequence and ratification timing unchanged (Q-5).
- **Purpose-scoped context, one skill per family** — `mimir-architecture-context` (module boundaries, entry points, boundary interfaces, cross-cutting concepts as embodied, existing architecture documentation, current-state view) feeds §5/§6/§8 and as-is documentation; `mimir-engineering-context` (current behavior, engineering conventions, test infrastructure with an executed baseline) feeds acceptance criteria and TDD, and runs after the architecture delegation so its scope can be the ratified write sets (ADR-0012, ADR-0015; user-directed). Each family's review skill owns the checklist for its shape (ADR-0013). *Tactic for Cost Proportionality and Clarity of Intent:* no dispatch gathers facts its consumer will not read; the discipline text (fact-rich, framing-poor, proof-per-finding) is duplicated verbatim rather than shared through a third skill.
- **Every optional step fires on a stated criterion** — architecture context gate (skip only when the structure is already established in conversation, ADR-0014), engineering context step (skip unless behavior must be characterized or test infrastructure is unestablished, ADR-0015), ratification checkpoint / persistence / Response (skip when `persistence=deferred`, ADR-0006), trigger check as one verdict line with no dispatch (ADR-0002). *Tactic for Cost Proportionality* (Q-3, Q-8).
- **Doctrine-not-code**: implementation uses Brokk's `system-prompts` / `documentation-writing`; review uses Heimdall's `system-prompt-review` / `documentation-review`; `scripts/validate.sh` is the mechanical check (ADR-0007, §8.4).
- **Odin prompt registration through templates only** — new `### Architecture` block in `shared-body.template.md` § Workflows and threshold lines in the three Communication Policy fragments, regenerated by `scripts/generate-odin-agents.sh` (ADR-0008). Trigger precedence: implementation intent → Engineering check; none → Architecture check (ADR-0002).
