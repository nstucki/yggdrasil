# 8.10 Review-Gated History

_Part of [Yggdrasil — Architecture (arc42)](../README.md) · [§8](README.md)._

The framework writes to a target project's version-control history through exactly one mechanism, and that mechanism is a review gate. **Implementing sessions never commit.** A `brokk-test-driven-development` session — in any phase, in any mode, whether or not the brief mentions commits — stops at a refactored green state, leaves the tree uncommitted, and reports the literal `Commits: none`; a reviewer treats any other value as blocking, and verifies with `git log` that `HEAD` did not move (`skills/tdd/brokk-test-driven-development/SKILL.md:10, 94-98, 112-114`; `skills/tdd/heimdall-tdd-review/SKILL.md:61, 103`). **A fresh commit session writes history, mechanically.** `brokk-tdd-commit` records one planned batch as one commit and decides nothing: the plan row fixes the packages, type, subject, and branch; the gating reviews fix the content — the union of the `Files changed` of every evidence block they cover; the suite fixes the moment — green, or red on exactly the plan's recorded baseline failures. It re-reads each gating review's first line itself, verifies `HEAD` against the pinned reference, verifies that the tree minus the baseline-dirty paths equals the reviewed union, stages one path per invocation and never a directory, checks the row's type against the diff's shape, re-runs the full suite on the tree after staging, commits with `git commit -m "<type>: <subject>"`, and verifies the result; every stop condition commits nothing and reports a fixed string (`skills/tdd/brokk-tdd-commit/SKILL.md:10-12, 60-71`). **The commit is itself reviewed.** `Focus: commit` checks, against ground truth, one commit with the pinned parent, a conforming branch, a path set equal to the reviewed union computed by the reviewer, a message equal to the plan row, a green suite at `HEAD`, only baseline-dirty leftovers, and every gating verdict passed (`skills/tdd/heimdall-tdd-review/SKILL.md:116-129`).

**Batches, not phases, are the unit of history.** The red, green, and refactor phases never produce separate commits; a `Phase: red` result is never a batch boundary, and `test:` is reserved for green tests-only packages. The planner's § Commit Plan Rules make every batch boundary a green tree state one suite run can prove — a wave plus its integration is one batch, sequential packages share a batch only with pairwise-disjoint write sets, a scaffold is its own batch committed before fan-out, and the commit count is minimal (`skills/tdd/kvasir-tdd-planning/SKILL.md:86-97`). The orchestrator applies one sequencing rule mechanically: a batch commits as soon as its last gating review passes and before the next batch's first package is dispatched, so `HEAD` is always the clean diff reference and a brief's reviewed-but-uncommitted list names only the current batch (`skills/tdd/odin-tdd-workflow/SKILL.md:60`).

**Message and branch conventions are fixed in the commit skill.** Four types — `feat:`, `fix:`, `refactor:`, `test:` — mapped from package kind (feature, fix, refactor, test; scaffold → `feat:` or `test:` when fixtures and declarations only; a mixed batch → the kind that delivers behavior, `feat:` > `fix:` > `refactor:` > `test:`); a subject imperative, lowercase, ≤ ~50 characters; a body only when the plan row supplies one. Commits land only on a branch prefixed `feature/`, `fix/`, or `refactor/`, created with `git switch -c` when the plan row says `create`, and never on `main`, `master`, `develop`, or an unprefixed branch, whatever the brief says (`skills/tdd/brokk-tdd-commit/SKILL.md:24-41`). The mapping is normative in that skill alone and echoed, as an echo, by the planner (`skills/tdd/kvasir-tdd-planning/SKILL.md:93, 95`).

**History is never rewritten, and the tree is never reverted.** The commit skill runs one git command per invocation, never amends, rebases, resets, force-updates, pushes, fetches, pulls, merges, cherry-picks, or reverts; the Brokk permission block denies `--amend` and stash destruction independently of the skill text (`skills/tdd/brokk-tdd-commit/SKILL.md:14`; `agents/brokk.md:35-41`). A blocked commit is cleared by a disclosed corrective commit; a blocked run leaves its uncommitted work in the tree, disclosed, for the user to direct (`skills/tdd/odin-tdd-workflow/SKILL.md:64-66`). The workspace never enters history: a `.yggdrasil-workspace/` path is never staged, and a missing ignore entry is noted, never added — that would be a project change no review covered (`skills/tdd/brokk-tdd-commit/SKILL.md:63, 71`).
