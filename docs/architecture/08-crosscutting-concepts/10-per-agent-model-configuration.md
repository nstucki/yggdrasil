# 8.10 Per-Agent Model Configuration

_Part of [Yggdrasil — Architecture (arc42)](../README.md) · [§8](README.md)._

Every agent carries `temperature:`; before this revision none carried `model:`, so all agents ran on the OpenCode session default (context Workfile § Model Configuration; repo-wide `grep '^\s*model:'` returns nothing). This revision introduces the concept for exactly one agent — and, after the user-directed amendment of 2026-09-21 (ADR-0009 amendment; R21), **entirely at the install site**. **Declaration: none in the repository.** The `model:` line originally designed for Eitri's template head was removed together with its warning comment (commit `e166fe5`); no agent file carries the key, and a fresh install runs Eitri on the session default model until an operator sets the override below. **Override, durable:** the operator sets `agent.eitri.model` in the configuration home's `opencode.json`; OpenCode merges JSON agent configuration over Markdown agent definitions, `setup.sh` never writes that file, so the override survives upgrades. **Override, volatile:** the operator adds a `model:` line to the installed `~/.config/opencode/agents/yggdrasil/eitri.md`; effective at once but removed by the next `setup.sh` (`README.md:111`), since the shipped file carries no such line. **Effect timing:** OpenCode reads agent configuration at session start, so a change takes effect on the next Eitri session — the next dispatch — with no regeneration, no repository edit, and no Yggdrasil-owned process to restart (NFR 6). **Non-mechanisms:** `custom-capabilities.yaml` documents a granted capability for planning and cannot select a model (`config-home/generate-capabilities.sh:272-321`); `temperature:` remains a per-agent sampling parameter, unrelated to model identity. **Toolchain neutrality:** `model:` is an ordinary frontmatter key — Check 1 requires only `name` and `description` (`scripts/validate.sh:8-10`), `frontmatter_value` ignores keys it is not asked for (`config-home/generate-capabilities.sh:124-141`), and Check 4 compares bytes regardless of keys. **Documentation:** `README.md` § Extending gains a "Configure the Designer's image model" subsection stating both override paths and their durability (WP-4). Full rationale and options in ADR-0009.
