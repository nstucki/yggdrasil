# 8.10 Per-Agent Model Configuration

_Part of [Yggdrasil — Architecture (arc42)](../README.md) · [§8](README.md)._

Every agent carries `temperature:`; before this revision none carried `model:`, so all agents ran on the OpenCode session default (context Workfile § Model Configuration; repo-wide `grep '^\s*model:'` returns nothing). This revision introduces the concept for exactly one agent — and, after the user-directed amendment of 2026-09-21 (ADR-0009 amendment; R21), **entirely at the install site**. **Declaration: none in the repository.** The `model:` line originally designed for Eitri's template head was removed together with its warning comment (commit `e166fe5`); no agent file carries the key, and a fresh install runs Eitri on the session default model until an operator sets the override below. **The one mechanism:** the operator sets `agent.eitri.model` in the configuration home's `opencode.json` (`$CONFIG_BASE/opencode.json`) to a real, image-capable `provider/model-id` from their installed provider setup; OpenCode merges JSON agent configuration over Markdown agent definitions, and `setup.sh` never writes that file, so the value survives every framework upgrade (`README.md:341-357`). **Not a supported route:** hand-adding a `model:` key to the installed `$CONFIG_BASE/agents/yggdrasil/eitri.md`. No shipped agent carries that key, whether a given OpenCode version honors it in Markdown frontmatter is unverified (R10), and the next `setup.sh` run overwrites the installed file and reverts the edit (`README.md:111`); this Workfile's earlier drafts described that edit as a "volatile override" — that description is withdrawn (ADR-0009, reconciliation amendment with commit `fd0101a`). **Effect timing:** OpenCode reads agent configuration at session start, so a change takes effect on the next Eitri session — the next dispatch — with no regeneration, no repository edit, and no Yggdrasil-owned process to restart (NFR 6). **Non-mechanisms:** `custom-capabilities.yaml` documents a granted capability for planning and cannot select a model (`config-home/generate-capabilities.sh:272-321`); `temperature:` remains a per-agent sampling parameter, unrelated to model identity. **Toolchain neutrality:** were a `model:` key ever shipped, it would be an ordinary frontmatter key — Check 1 requires only `name` and `description` (`scripts/validate.sh:8-10`), `frontmatter_value` ignores keys it is not asked for (`config-home/generate-capabilities.sh:124-141`), and Check 4 compares bytes regardless of keys; none ships today. **Documentation:** `README.md` § Extending carries the "Configure the Designer's Image Model" subsection (`README.md:341-357`, WP-4 as corrected by `fd0101a`) stating the single `opencode.json` route, its durability, and that the installed-file edit is not supported. Full rationale and options in ADR-0009.
