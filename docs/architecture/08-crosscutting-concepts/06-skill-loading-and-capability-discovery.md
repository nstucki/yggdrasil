# 8.6 Skill Loading and Capability Discovery

_Part of [Yggdrasil — Architecture (arc42)](../README.md) · [§8](README.md)._

Each role loads only skills matching its prefix — Odin `capability-inventory` and `odin-*`, Mimir `mimir-*`, Brokk `brokk-*`, **Eitri `eitri-*`**, and so on — enforced by the `skill` permission allowlist (`agents/odin-autonomous.md:8-11`; `agents/mimir.md:63-65`; §5.1.2 Eitri frontmatter). Odin loads the generated `capability-inventory` skill once per session before planning; the Agent Selection Guide is routing doctrine, not a capability list, and its role names match the inventory's section names — after this revision, six: Researcher, Implementer, Reviewer, Strategist, Communicator, **Designer** (`scripts/odin-generator/shared-body.template.md:21-29`). The inventory is generated install-side by `config-home/generate-capabilities.sh` from skill frontmatter plus `custom-capabilities.yaml`, and is regenerated on every install (`README.md:117, 118, 127`; `scripts/README.md:162-166`). A role with no shipped skill — Eitri's case in this revision (C15) — still appears, carrying the agent's `description:` and `(none)` for skills (`config-home/generate-capabilities.sh:245-270, 354-364` pattern applied to the new section), so Odin discovers the Designer's existence and purpose through the same mechanism as every other role. Validator Checks 5 and 6 keep skill descriptions and subagent prompts free of agent names, `eitri` included, so the inventory can be role-phrased (`scripts/validate.sh:450-451, 520`).
