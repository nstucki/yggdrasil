# 8.5 Trigger-Gated Packaged Workflows

_Part of [Yggdrasil — Architecture (arc42)](../README.md) · [§8](README.md)._

Four workflows — Deliberation Council, Research, Architecture, Software Engineering — are invoked whole rather than composed. Each has invariant trigger rules in Odin's shared body (command → invoke; explicit language → invoke; a named suggestion candidate → per Communication Policy; factual or executable request → skip), a one-line triggering verdict, and a dedicated `odin-*` skill that Odin loads on `invoke` and that carries the full mechanism, constraints, cost model, and the workflow-fixed `Deliverable:` line (`agents/odin-autonomous.md:172-219`; `skills/architecture/odin-architecture-workflow/SKILL.md:10-24`). Standing rules: every workflow ends at the Final Review Gate; the Kvasir Consultation Check records `skip — packaged workflow`; a workflow nested in a composite plan does not exempt the composite (`agents/odin-autonomous.md:176-179`). A fifth packaged workflow, TDD, carries the same doctrine-skill shape — full mechanism, cost model, fixed `Deliverable:`, Consultation-Check exemption — but no trigger verdict: it is invoked only as a stage, and is standalone by design so that a trigger can be added without touching it (`skills/engineering/odin-tdd-workflow/SKILL.md:18-30`).

Workflows compose by **staging, not by contract**. An enclosing workflow loads the inner workflow's skill and runs it to completion as one of its own steps, with the inner workflow's gates intact and its Response folded into the enclosing one; no request line and no result line pass between them. The Software Engineering workflow is composed this way twice over: its architecture stage runs the Architecture workflow — context gate, drafting, ratification checkpoint, persistence, and their reviews — and its TDD stage runs the TDD workflow — context gate, plan, plan checkpoint, reviewed packages, integration, and review-gated commits — and the enclosing plan re-ratifies, re-persists, re-plans, re-reviews, and re-commits nothing (`skills/engineering/odin-engineering-workflow/SKILL.md:12, 26, 47-53, 57-62`; `skills/architecture/odin-architecture-workflow/SKILL.md:29, 59`; `skills/engineering/odin-tdd-workflow/SKILL.md:28, 62`; `agents/odin-autonomous.md:213`, generated from `scripts/odin-generator/shared-body.template.md:186`). What the enclosing workflow keeps for itself is the shape verdict over the two optional steps, `Engineering shape: analysis=<yes/no — reason>, architecture=<yes/no — reason>`, and the Response; each stage's checkpoint is a steering point of the enclosing run, and the enclosing cost model names each stage's dispatch count as a term (`odin-engineering-workflow/SKILL.md:24, 35-43, 72`). Trigger ownership follows: architecture language *with* implementation intent is the Engineering check's, *without* it the Architecture check's (`agents/odin-autonomous.md:207`).
