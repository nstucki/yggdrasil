# 8.5 Trigger-Gated Packaged Workflows

_Part of [Yggdrasil — Architecture (arc42)](../README.md) · [§8](README.md)._

Four workflows — Deliberation Council, Research, Architecture, Software Engineering — are invoked whole rather than composed. Each has invariant trigger rules in Odin's shared body (command → invoke; explicit language → invoke; a named suggestion candidate → per Communication Policy; factual or executable request → skip), a one-line triggering verdict, and a dedicated `odin-*` skill that Odin loads on `invoke` and that carries the full mechanism, constraints, cost model, and the workflow-fixed `Deliverable:` line (`agents/odin-autonomous.md:172-219`; `skills/architecture/odin-architecture-workflow/SKILL.md:10-24`). Standing rules: every workflow ends at the Final Review Gate; the Kvasir Consultation Check records `skip — packaged workflow`; a workflow nested in a composite plan does not exempt the composite (`agents/odin-autonomous.md:176-179`).

Workflows compose by **staging, not by contract**. An enclosing workflow loads the inner workflow's skill and runs it to completion as one of its own steps, with the inner workflow's gates intact and its Response folded into the enclosing one; no request line and no result line pass between them. The Software Engineering workflow runs the Architecture workflow this way as its architecture stage — the stage's own context gate, drafting step, ratification checkpoint, and persistence review run inside it, and the enclosing plan re-ratifies and re-persists nothing (`skills/engineering/odin-engineering-workflow/SKILL.md:26, 50-52, 97`; `skills/architecture/odin-architecture-workflow/SKILL.md:29, 59`; `agents/odin-autonomous.md:213`, generated from `scripts/odin-generator/shared-body.template.md:186`). Trigger ownership follows: architecture language *with* implementation intent is the Engineering check's, *without* it the Architecture check's (`agents/odin-autonomous.md:207`).
