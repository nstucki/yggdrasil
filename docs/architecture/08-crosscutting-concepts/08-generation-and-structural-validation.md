# 8.8 Generation and Structural Validation

_Part of [Yggdrasil — Architecture (arc42)](../README.md) · [§8](README.md)._

All **nine** agent definitions are derived: Odin modes from a preamble, a shared body, and a policy fragment; subagents from a template head, shared workspace/tooling/memory fragments, and a workflow tail (`scripts/README.md:5-57`; `scripts/generate-subagents.sh:103-121`). The specialist roster is not a manifest but a set of literal lists that must agree: `SUBAGENTS` and `WORKFILE_AUTHORS` in the generator, `SUBAGENT_NAMES` (twice) and `ALL_AGENT_NAMES` in the validator, the `case` arm and the description loop in the capability generator, the loops in the two smoke tests, and Odin's `task:` allowlist (ADR-0011 enumerates them with lines). `validate.sh` runs ten read-only checks — frontmatter, skill sections and slugs, byte-identity of all agents, subagent isolation, capability mirror, Odin parity markers, command files, mandatory-skill isolation, no license texts — and three smoke tests assert generator parity for CI (`scripts/validate.sh:1-60`; `.github/workflows/ci.yml:41-54`). The maintainer workflow is edit source → regenerate → validate → commit source (`scripts/README.md:105-151`); adding a specialist is that workflow applied to every roster list in one commit.
