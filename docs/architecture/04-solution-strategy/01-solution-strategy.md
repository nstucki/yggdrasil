# 4. Solution Strategy

_Part of [Yggdrasil — Architecture (arc42)](../README.md) · [§4](README.md)._

The strategy the system follows, summarized from the decisions logged in §9. Items 1–8 record decisions already in force (ADR-0001 – ADR-0008, `Kind: as-is`); items 9–11 summarize the decisions ADR-0009 – ADR-0014 that shape the architecture-documentation subsystem; item 12 summarizes ADR-0015 – ADR-0018, which record the Architecture workflow's single form and supersede the mode-, review-, and scaffold-specific clauses of ADR-0010 – ADR-0014.

1. **One orchestrator, five role-bound specialists, hub-and-spoke** (ADR-0001). Odin alone holds the `task` permission and may reach exactly the five specialists; specialists cannot task each other and never reason about the user's Deliverable. Odin never performs specialist work and never reads artifact files — it acts on executive summaries and routes paths (`agents/odin-autonomous.md:6-19, 38-40, 72, 81`). Serves system goal 2 (role isolation).

2. **Mandatory independent review by a dedicated reviewer** (ADR-0002). Every Mimir and Brokk Subtask receives a dedicated Heimdall review; every Orchestration Task ends at a Final Review Gate in a fresh Heimdall session; a verdict is `PASS`, `PASS-WITH-NOTES`, or `BLOCKED` and is never re-reviewed; failed reviews follow a classification ladder capped at three fix rounds (`agents/odin-autonomous.md:237-279`). Serves system goal 1 (independent verification).

3. **Least-privilege permission blocks as the only enforcement mechanism** (ADR-0003). Every agent frontmatter begins with `"*": deny` and allows tools per role, with `edit` scoped by path glob and `bash` by command pattern, including shell-escape guards on `git` (`agents/mimir.md:6-68`; `agents/brokk.md:6-64`). Serves system goals 2 and 1.

4. **Generated agent definitions with byte-identity validation** (ADR-0004). Odin's three modes are one shared body plus a mode-specific Communication Policy fragment; each subagent is a template head plus shared workspace/tooling/memory fragments plus a workflow tail; `validate.sh` and two smoke tests assert parity (`scripts/README.md:5-103`; `scripts/generate-subagents.sh:103-121`). Serves system goal 3 (reproducibility).

5. **Two stores with opposite lifecycles** (ADR-0005). Transient, gitignored Workfiles in `.yggdrasil-workspace/` for intra-task exchange, written by Mimir/Kvasir/Heimdall/Bragi and read-only for Brokk; persistent, git-tracked Memories in `.yggdrasil-memory/` written only by reviewed pipelines (`agents/odin-autonomous.md:74-90`; `agents/brokk.md:53-56, 89-91`). Serves system goals 4 and 2.

6. **Trigger-gated packaged workflows as Odin-prefixed skills** (ADR-0006). Research, Architecture, Software Engineering, and Deliberation Council are each a one-line triggering verdict in Odin's prompt plus a full-mechanism `odin-*` skill loaded on invoke; a packaged workflow is exempt from the Kvasir Consultation Check and inherits the standing review rules (`agents/odin-autonomous.md:172-219`). Serves system goals 1 and 5.

7. **Three Odin modes that differ only in Communication Policy** (ADR-0007). Autonomous, Guided, and Interactive share every orchestration rule; the mode fragment sets whether Odin asks, suggests, or auto-proceeds at each checkpoint (`scripts/README.md:11-16`; `agents/odin-autonomous.md:280-302`). Serves the user-steering interest in §1.3.

8. **Memory governed by command-triggered, reviewed pipelines** (ADR-0008). Remember, Dream, and Forget are the only writers; every write is reviewed; Forget is confirmed; Memories are consulted as leads and verified against live sources before use (`agents/odin-autonomous.md:84-90`; `skills/memories/odin-memory-system/SKILL.md:24-61`). Serves system goals 4 and 1.

9. **One long-term-relevance test, stated once, owned by the author and checked mechanically at persistence** (ADR-0010, ADR-0012, ADR-0016). The test — content belongs in §1–§12 only if it stays true and useful after the triggering task completes — is written once in the drafting skill (`skills/architecture/kvasir-software-architecture/SKILL.md` § Boundaries), narrows what the context step gathers (`skills/architecture/mimir-architecture-context/SKILL.md:25`), and — because the draft receives no review — is enforced at the persistence review for its pattern-matchable subset: three greps under the persisted target, any hit blocking (`skills/architecture/heimdall-architecture-review/SKILL.md:94, 97`). Persisted sections cite only document-stable references — repository paths, section numbers, decision IDs, and requirement IDs defined in §1.1 — so nothing in them resolves against a workspace that will be gone. **Tactics per subsystem goal:** Durability — the test plus the reference rule plus the persistence greps; Clarity — typed omission markers (item 10) and a report that states the scope line beside the decisions; Consistency — one test text, one workflow form, zero scope exemptions; Usability — implementation-phase content is named by tell-tales and excluded from §5 and §9.

10. **A closed set of three typed omission markers** (ADR-0011). `_Omitted — not architecturally significant for this objective_` (scope), `_Omitted — no evidence in context Workfile_` (evidence), `_Not affected by this change_` (unaffected by this update). The drafter picks by document scope; the persistence step copies a scope or evidence marker verbatim into the section index and never writes the unaffected one, and the persistence review blocks when it finds that wording in the tree (`skills/architecture/heimdall-architecture-review/SKILL.md:91`). The `Section scope:` header line lists the included and the omitted sections. Serves Clarity (goal 2) and Consistency (goal 4).

11. **Document-granular update deltas with explicit supersession** (ADR-0014). In update-delta scope the layout map names only the topic documents the delta writes; a document of an included section that the map does not name is carried forward byte-identical, and a document the delta retires is named in a `→ superseded — <reason>` row. The persistence step replaces exactly the named documents and lists as superseded exactly the rows that say so (`skills/architecture/brokk-architecture-persistence/SKILL.md:134`). Serves Maintainability (goal 3): a delta that changes one building block re-authors one document. Framework skill changes land in the repository's `skills/architecture/` tree and reach the runtime through `setup.sh` (ADR-0009).

12. **One Architecture workflow — mode-less, stage-composable, with an unreviewed draft and a layout-creating persistence step** (ADR-0015, ADR-0016, ADR-0017, ADR-0018). The workflow packages `[Context → Review] │ Draft │ Checkpoint │ Persist → Review │ Response` over five skills (`skills/architecture/odin-architecture-workflow/SKILL.md:10-16`). No mode is chosen: the objective fixes what the document holds, and the drafter's two-fact check of the target fixes `Document scope:` (`seed` | `update delta`) and `Records from:` (ADR-0015). The drafting step is the one node without a review, permanently; its gates are the ratification checkpoint and the persistence review, which re-derives the target's baseline state and blocks on disagreement with the header (ADR-0016; `:14, 55-57, 79`). The persistence step creates the twelve-folder layout when the target is absent and the header reads `seed` — no scaffold step and no template skill precede drafting (ADR-0017; `:55`; `skills/architecture/brokk-architecture-persistence/SKILL.md:42`). An enclosing workflow runs this one to completion as a stage — no request line, no result line; the Deliverable is workflow-fixed (ADR-0018; `:18-22, 29`; `skills/engineering/odin-engineering-workflow/SKILL.md:26, 50-52`). Serves Consistency (goal 4: one form) and Maintainability (goal 3: four dispatches when context is established, six when it is gathered, two when persistence is declined — `:81`); trades a review of the draft for the two gates named (system goal 1 — see §11 R3, R11).

**Cross-cutting tactic named by the doctrine:** forcing-function verdict lines. Odin must state a one-line recorded verdict before every consequential branch — `Deliverable:`, `Kvasir check:`, `Research check:`, `Architecture check:`, `Engineering check:`, `Deliberation check:` — so that a skipped step is visibly self-contradictory rather than silently omitted (`agents/odin-autonomous.md:119-123, 160, 185, 195, 205, 215`). The Architecture workflow's own hand-off lines — `Context: skipped — <reason>`, `Section scope:`, `Verdict:`, `Ratification:` — are the same tactic applied inside one workflow (§5.2); the `Deliverable:` line is fixed by the workflow skill and recorded at Odin's top level (`skills/architecture/odin-architecture-workflow/SKILL.md:18-22, 37, 49-51`).
