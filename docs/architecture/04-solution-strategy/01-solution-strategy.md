# 4. Solution Strategy

_Part of [Yggdrasil — Architecture (arc42)](../README.md) · [§4](README.md)._

The strategy the system follows, summarized from the decisions logged in §9. Items 1–8 record decisions already in force (ADR-0001 – ADR-0008, `Kind: as-is`); items 9–11 summarize the decisions ADR-0009 – ADR-0014 that shape the architecture-documentation subsystem.

1. **One orchestrator, five role-bound specialists, hub-and-spoke** (ADR-0001). Odin alone holds the `task` permission and may reach exactly the five specialists; specialists cannot task each other and never reason about the user's Deliverable. Odin never performs specialist work and never reads artifact files — it acts on executive summaries and routes paths (`agents/odin-autonomous.md:6-19, 38-40, 72, 81`). Serves system goal 2 (role isolation).

2. **Mandatory independent review by a dedicated reviewer** (ADR-0002). Every Mimir and Brokk Subtask receives a dedicated Heimdall review; every Orchestration Task ends at a Final Review Gate in a fresh Heimdall session; a verdict is `PASS`, `PASS-WITH-NOTES`, or `BLOCKED` and is never re-reviewed; failed reviews follow a classification ladder capped at three fix rounds (`agents/odin-autonomous.md:237-279`). Serves system goal 1 (independent verification).

3. **Least-privilege permission blocks as the only enforcement mechanism** (ADR-0003). Every agent frontmatter begins with `"*": deny` and allows tools per role, with `edit` scoped by path glob and `bash` by command pattern, including shell-escape guards on `git` (`agents/mimir.md:6-68`; `agents/brokk.md:6-64`). Serves system goals 2 and 1.

4. **Generated agent definitions with byte-identity validation** (ADR-0004). Odin's three modes are one shared body plus a mode-specific Communication Policy fragment; each subagent is a template head plus shared workspace/tooling/memory fragments plus a workflow tail; `validate.sh` and two smoke tests assert parity (`scripts/README.md:5-103`; `scripts/generate-subagents.sh:103-121`). Serves system goal 3 (reproducibility).

5. **Two stores with opposite lifecycles** (ADR-0005). Transient, gitignored Workfiles in `.yggdrasil-workspace/` for intra-task exchange, written by Mimir/Kvasir/Heimdall/Bragi and read-only for Brokk; persistent, git-tracked Memories in `.yggdrasil-memory/` written only by reviewed pipelines (`agents/odin-autonomous.md:74-90`; `agents/brokk.md:53-56, 89-91`). Serves system goals 4 and 2.

6. **Trigger-gated packaged workflows as Odin-prefixed skills** (ADR-0006). Research, Architecture, Software Engineering, and Deliberation Council are each a one-line triggering verdict in Odin's prompt plus a full-mechanism `odin-*` skill loaded on invoke; a packaged workflow is exempt from the Kvasir Consultation Check and inherits the standing review rules (`agents/odin-autonomous.md:172-219`). Serves system goals 1 and 5.

7. **Three Odin modes that differ only in Communication Policy** (ADR-0007). Autonomous, Guided, and Interactive share every orchestration rule; the mode fragment sets whether Odin asks, suggests, or auto-proceeds at each checkpoint (`scripts/README.md:11-16`; `agents/odin-autonomous.md:280-302`). Serves the user-steering interest in §1.3.

8. **Memory governed by command-triggered, reviewed pipelines** (ADR-0008). Remember, Dream, and Forget are the only writers; every write is reviewed; Forget is confirmed; Memories are consulted as leads and verified against live sources before use (`agents/odin-autonomous.md:84-90`; `skills/memories/odin-memory-system/SKILL.md:24-61`). Serves system goals 4 and 1.

9. **One long-term-relevance test, stated once, applied at three points of the Architecture workflow** (ADR-0010, ADR-0012, ADR-0013). The test — content belongs in §1–§12 only if it stays true and useful after the triggering task completes — is written once in the drafting skill (`skills/architecture/kvasir-software-architecture/SKILL.md`), narrows what the context step gathers (`skills/architecture/mimir-architecture-context/SKILL.md`), and is enforced by a blocking, judgment-based criterion in the design review (`skills/architecture/heimdall-architecture-review/SKILL.md`, `Focus: document`, both modes). Persisted sections cite only document-stable references — repository paths, section numbers, decision IDs, and requirement IDs defined in §1.1 — so nothing in them resolves against a workspace that will be gone. **Tactics per subsystem goal:** Durability — the test plus the reference rule; Clarity — typed omission markers (item 10) and a report that states scope with reasons; Consistency — one test text, referenced by three skills, zero mode exemptions; Usability — implementation-phase content is named by tell-tales and excluded from §5 and §9.

10. **A closed set of three typed omission markers** (ADR-0011). `_Omitted — not architecturally significant for this objective_` (scope), `_Omitted — no evidence in context Workfile_` (evidence), `_Not affected by this change_` (unaffected by this update). The drafter picks by document scope and mode from a fixed table; the reviewer checks the string, the persistence step copies it. The `Section scope:` line carries the type beside each omitted section. Serves Clarity (goal 2) and Consistency (goal 4).

11. **Document-granular update deltas with explicit supersession** (ADR-0014). In update-delta scope the layout map names only the topic documents the delta writes; a document of an included section that the map does not name is carried forward untouched, and a document the delta retires is named in a `→ superseded — <reason>` row. The persistence step replaces exactly the named documents and lists as superseded exactly the rows that say so. Serves Maintainability (goal 3): a delta that changes one building block re-authors one document. Framework skill changes that implement items 9–11 land in the repository's `skills/architecture/` tree and reach the runtime through `setup.sh` (ADR-0009).

**Cross-cutting tactic named by the doctrine:** forcing-function verdict lines. Odin must state a one-line recorded verdict before every consequential branch — `Deliverable:`, `Kvasir check:`, `Research check:`, `Architecture check:`, `Engineering check:`, `Deliberation check:` — so that a skipped step is visibly self-contradictory rather than silently omitted (`agents/odin-autonomous.md:119-123, 160, 185, 195, 205, 215`). The Architecture workflow's own hand-off lines — `Scaffold result:`, `Section scope:`, `Verdict:`, `Ratification:` — are the same tactic applied inside one workflow (§5.2).
