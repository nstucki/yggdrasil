# 4. Solution Strategy

_Part of [Yggdrasil — Architecture (arc42)](../README.md) · [§4](README.md)._

Items 1–8 record the strategy the system follows, summarized from the decisions in force (ADR-0001–ADR-0008, `Status: Accepted`). Item 1 is revised and items 9–11 are added by this revision; the revision items are `Status: Proposed` until ratified.

1. **One orchestrator, six role-bound specialists, hub-and-spoke** (ADR-0001, superseded in its count by ADR-0011). Odin alone holds the `task` permission and may reach exactly the six specialists — Mimir, Brokk, Heimdall, Bragi, Kvasir, Eitri; specialists cannot task each other and never reason about the user's Deliverable. Odin never performs specialist work and never reads artifact files — it acts on executive summaries and routes paths (`agents/odin-autonomous.md:6-19, 38-40, 72, 81`; `scripts/odin-generator/preamble.template.md:12-18`). Serves S2 (role isolation) and, for this revision, **Consistency** — Eitri enters through the same allowlist line and the same Agent Selection Guide row every specialist has, with no Eitri-specific conditional anywhere in Odin.

2. **Mandatory independent review by a dedicated reviewer** (ADR-0002). Every Mimir and Brokk Subtask — and, by the same principle, every Eitri Subtask, since Eitri writes Artifacts — receives a dedicated Heimdall review; every Orchestration Task ends at a Final Review Gate in a fresh Heimdall session; a verdict is `PASS`, `PASS-WITH-NOTES`, or `BLOCKED` and is never re-reviewed; failed reviews follow a classification ladder capped at three fix rounds (`agents/odin-autonomous.md:237-279`; `scripts/odin-generator/shared-body.template.md:150, 225` revised by WP-2). Serves S1.

3. **Least-privilege permission blocks as the only enforcement mechanism** (ADR-0003; Eitri's profile in ADR-0010). Every agent frontmatter begins with `"*": deny` and allows tools per role, with `edit` scoped by path glob and `bash` by command pattern. Eitri's block allows `edit` on workspace markdown and image-file globs only, denies Memory paths explicitly, grants `read`/`glob`/`grep`, and grants no shell and no network (`agents/mimir.md:6-68`; `agents/brokk.md:6-64`; §5.1.2). Serves S2 and, for this revision, **Consistency** (Bragi-shaped read surface) with the stated additions **Clarity** demands be explicit.

4. **Generated agent definitions with byte-identity validation** (ADR-0004). Odin's three modes are one shared body plus a mode-specific Communication Policy fragment; each subagent is a template head plus shared workspace/tooling/memory fragments plus a workflow tail; `validate.sh` and two smoke tests assert parity. Eitri is generated exactly this way — `eitri.template.md` + workspace + tooling + memory fragments + `eitri.workflow.template.md` — and is added to `WORKFILE_AUTHORS` because he writes manifest Workfiles (`scripts/generate-subagents.sh:68-74, 103-121`). Serves S3 and **Maintainability**.

5. **Two stores with opposite lifecycles** (ADR-0005). Transient, gitignored Workfiles in `.yggdrasil-workspace/` for intra-task exchange, written by Mimir/Kvasir/Heimdall/Bragi and now Eitri (image manifests) and read-only for Brokk; persistent, git-tracked Memories in `.yggdrasil-memory/` written only by reviewed pipelines. Eitri's image files are Artifacts, never Workfiles (`agents/odin-autonomous.md:74-90`; `agents/brokk.md:53-56, 89-91`). Serves S4 and S2.

6. **Trigger-gated packaged workflows as Odin-prefixed skills** (ADR-0006). Research, Architecture, Software Engineering, and Deliberation Council are each a one-line triggering verdict in Odin's prompt plus a full-mechanism `odin-*` skill loaded on invoke. This revision adds no workflow and no command (C15) (`agents/odin-autonomous.md:172-219`). Serves S1 and S5.

7. **Three Odin modes that differ only in Communication Policy** (ADR-0007). Autonomous, Guided, and Interactive share every orchestration rule, so Eitri's registration in the shared preamble and body reaches all three modes in one edit (`scripts/README.md:11-16`; `agents/odin-autonomous.md:280-302`). Serves the user-steering interest in §1.3 and **Maintainability**.

8. **Memory governed by command-triggered, reviewed pipelines** (ADR-0008). Remember, Dream, and Forget are the only writers; Eitri's `edit` block denies `.yggdrasil-memory/**` explicitly on top of the standing prose boundary (`agents/odin-autonomous.md:84-90`; `skills/memories/odin-memory-system/SKILL.md:24-61`). Serves S4 and S1.

9. **Image model selected at the install site via OpenCode's per-agent override in `opencode.json`; no `model:` key in any repository agent file** (ADR-0009, new; amended 2026-09-21 by user direction — R21). An operator sets `agent.eitri.model` in the configuration home's `opencode.json`, durably across `setup.sh` upgrades — the single supported route; hand-adding a `model:` line to the installed `eitri.md` is not supported (unverified host support, reverted by `setup.sh`, no shipped key — `README.md:357`). No repository edit, no regeneration, no restart of anything Yggdrasil owns — and, after the amendment, no in-repo default or signal either: a fresh install runs Eitri on the session default until the override is set. Serves **Configurability** (override half) and **Consistency** (full frontmatter parity with the five peers); the withdrawn in-repo half is an accepted trade-off.

10. **Designer permission profile: workspace-markdown plus image-file `edit` allowlist, unscoped `read`/`glob`/`grep`, no shell, no network; Memory protected by construction, not by explicit deny** (ADR-0010, new; amended 2026-09-21 by user direction — R21). The baseline C13 grants are enforced by glob; the three additions beyond the literal baseline each carry a stated functional need in the record; the two explicit Memory deny globs originally ratified were removed, which brings Eitri's `edit` block into line with every other Workfile-writing peer — none of which carries a Memory deny glob. Serves S2, **Clarity**, and **Consistency**.

11. **Designer registered as the sixth specialist by extending the existing roster lists in place; a `designer` role keyed on the `eitri-` prefix; supersedes ADR-0001** (ADR-0011, new). The six hardcoded roster occurrences (`scripts/generate-subagents.sh:68, 74`; `scripts/validate.sh:351, 450-451, 486, 520`; `config-home/generate-capabilities.sh:180-189, 256-269, 323-433`; `scripts/ci-smoke-subagent-generator.sh:40, 68-72`; `scripts/ci-smoke-generator.sh:105-109, 121`; `scripts/odin-generator/preamble.template.md:12-18`) each gain Eitri; the capability inventory renders a sixth `### Designer` section; no roster manifest is introduced now (recorded as debt R12). Serves **Consistency** and **Maintainability** — by analogy, not by abstraction — under C2.

**Cross-cutting tactic named by the doctrine:** forcing-function verdict lines. Odin must state a one-line recorded verdict before every consequential branch — `Deliverable:`, `Kvasir check:`, `Research check:`, `Architecture check:`, `Engineering check:`, `Deliberation check:` — so that a skipped step is visibly self-contradictory rather than silently omitted (`agents/odin-autonomous.md:119-123, 160, 185, 195, 205, 215`). This revision adds no verdict line; Eitri's own return message carries a fixed `Image:` summary line (§5.1.2) so that Odin and Heimdall can act on it without reading the file.
