# ADR-0020: Only a fresh, reviewed commit session writes history — after every gating review passes

- **Status:** Accepted
- **Date:** 2026-09-24
- **Kind:** recorded (evidence: `skills/engineering/brokk-tdd-commit/SKILL.md:3, 10-22, 43-71, 86-94`; `skills/engineering/brokk-test-driven-development/SKILL.md:3, 10, 94-98, 102, 112-114, 145`; `skills/engineering/heimdall-tdd-review/SKILL.md:15-17, 47, 61, 103, 107, 113-129, 164-165`; `skills/engineering/odin-tdd-workflow/SKILL.md:12-14, 47-49, 58-60, 64-66, 75, 84-88, 96-100, 105`; `scripts/odin-generator/shared-body.template.md:150`; `agents/brokk.md:10-41`)

## Context

Under the inline form, the implementing session committed its own work at the end of a green phase, and in split-phase mode a `Phase: red` result could be committed as `test:` — so history received a diff before any reviewer had read it, a failing test suite could be a commit, and a staging error could make the committed set differ from what the review later covered. The framework's first quality goal is that no output reaches the user, the project, or Memory without a review by a session that did not produce it (§1.2); a target project's version-control history is an output the doctrine had not yet placed behind a gate. Goals affected: system goal 1 (independent verification — of history), goal 2 (role isolation — the session that judges the tree and the session that records it), goal 4 (traceability — a commit's path set equals the reviewed diffs).

## Decision

**No session other than a `brokk-tdd-commit` session commits, in any mode** (`odin-tdd-workflow/SKILL.md:84`). An implementing or integrating session "never records a commit, in any phase and in any mode, whether or not the brief mentions one"; it stops at a refactored green state, hands the uncommitted tree to review, and its evidence block carries the literal `Commits: none` — "a brief that asks this session to commit is a defect in the brief" (`brokk-test-driven-development/SKILL.md:10, 94-98, 112-114`). The reviewer verifies `HEAD` against the pinned value with `git log`, and a moved `HEAD` under `Focus: package` or `Focus: integration` is "a commit by a session that may not commit, blocking by itself" (`heimdall-tdd-review/SKILL.md:61, 103, 107, 114`).

**A fresh Brokk session commits one batch, mechanically, after the gate.** Odin dispatches it only when every review the batch's `Gate` names reads `PASS` or `PASS-WITH-NOTES` — "never before, never on BLOCKED" (`odin-tdd-workflow/SKILL.md:58`) — and the session enforces the same gate a second time by reading the first line of every gating review Workfile itself, stopping with `gate not met — <path>: <verdict>` otherwise (`brokk-tdd-commit/SKILL.md:60`). It decides nothing: the plan row fixes what, the reviews fix the content — the reviewed union — and the suite fixes when (`:10-12`). It verifies `HEAD` equals the pinned reference, verifies the tree minus the baseline-dirty paths equals the reviewed union, stages one path per invocation and never `git add .`, checks the row's type against the diff's shape, re-runs the full suite after staging, commits `<type>: <subject>` verbatim from the row, and verifies the result; every stop condition commits nothing and reports a fixed string (`:61-71`). A `.yggdrasil-workspace/` path is never staged and a missing ignore entry is never added (`:63, 71`).

**The commit is itself reviewed.** The standing rule that every Mimir/Brokk dispatch is reviewed "without exception" (`shared-body.template.md:150`) covers the commit session because it is a Brokk session; "no exception is claimed for it" (`odin-tdd-workflow/SKILL.md:14`). `Focus: commit` checks exactly one commit with the pinned parent, a conforming branch, a path set equal to the reviewed union computed by the reviewer, a message equal to the plan row, green at `HEAD`, only baseline-dirty leftovers, and every gating verdict passed (`heimdall-tdd-review/SKILL.md:116-127`). A blocked commit is already history: it is cleared by one corrective commit for a staging omission, disclosed with the original; anything else ends the run; this workflow never rewrites history and never reverts, stashes, or deletes working-tree changes (`odin-tdd-workflow/SKILL.md:64-66`; `heimdall-tdd-review/SKILL.md:129`). The Brokk permission block denies `--amend` and stash destruction independently of the skill text (`agents/brokk.md:35-41`).

## Consequences

- **Positive:** history is behind the same gate as every other output — a review a different session performed, verified against ground truth; the committed set is provably the reviewed set (committed = staged = reviewed union, checked by the committer and again by the reviewer); the reviewed diff is against a `HEAD` that never moves under an implementing session, so a package review reads exactly one package's work; the review-before-commit invariant is enforced twice, in the dispatch condition and in the committer's own re-read.
- **Negative:** two dispatches per batch (commit + review) on top of the package reviews; the commit review's artifact is irreversible when it runs, so a defect it finds stays in the branch's log beside its correction (§11 R22); a red suite after staging leaves the reviewed union staged in the index — disclosed by the stop string, inspected by the next session, undone by no one (`brokk-tdd-commit/SKILL.md:66`; §11 R21, closed).
- **Becomes harder:** "checkpoint" commits during a long package, committing a partial wave, or committing on a verbal or promised review — each is an anti-pattern by name (`odin-tdd-workflow/SKILL.md:96-98`; `brokk-tdd-commit/SKILL.md:86, 91`); repairing a bad commit in place — the fix is a new commit and a report.
