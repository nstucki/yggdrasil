# ADR-0009: Dedicated mandatory `skills/architecture/` directory holding the workflow skill and the relocated architecture specialists

- **Status:** Accepted
- **Date:** 2026-09-18
- **Revision 1:** 2026-09-18 — the original recommendation (option A, `skills/engineering/`) was overridden by user direction at the plan checkpoint: architecture doctrine must not live inside the engineering workflow's directory. The document was never persisted, so this record is amended in place rather than superseded; option A is retained below, marked **Rejected (user-directed)**.
- **Revision 2:** 2026-09-18 — user direction extends the relocation to `mimir-codebase-context` (option D replaces C) and, with ADR-0011, renames the template to `brokk-arc42-template`.

## Context
AC-15 allows `skills/architecture/` or `skills/engineering/`. The repo convention is one mandatory feature directory per workflow family, each holding the Odin doctrine skill plus the specialists that serve it (context research §6). Membership is registered in `MANDATORY_SKILL_DIRS` at `setup.sh:167` and `validate.sh:762`; a `skills/*/` directory *not* listed there is treated as an optional bundle by both — so a new directory must be registered or (i) mandatory-only installs omit it and (ii) Check 9 fails for any mandatory skill referencing its slugs (C-4). All skill-to-skill coupling is load-by-name and layout-agnostic (C-11); the only hardcoded skill path in the repo outside README is in `LICENSES/CC-BY-SA-4.0-arc42.txt` (C-10). `setup.sh` never deletes under the destination, so relocated directories leave stale copies in existing installs (C-6). Goals: Reusability, Doctrine Minimization, Backward Compatibility, Cost Proportionality.

## Decision
We use **D** (Revision 2; the earlier decision was C). `skills/architecture/` becomes the fifth mandatory feature directory, containing `odin-architecture-workflow` (new), `heimdall-architecture-review` (new, ADR-0010), the relocated `kvasir-software-architecture`, `brokk-architecture-persistence`, `mimir-codebase-context` (contents byte-identical after the move), and the relocated-and-renamed `brokk-arc42-template` (ADR-0011; two rename-forced edits, §5.1.10). **Re-opened `mimir-codebase-context` call:** the earlier "it is shared, so it stays" reasoning is symmetric — both workflows dispatch it by name and neither owns it by location — so directory placement is a convention choice, not a coupling choice; placing it with the family that also reverse-engineers whole systems (document mode) is at least as natural, and the user directed it. **Zero functional impact on `odin-engineering-workflow` re-verified the same way as for the other three:** its only references are load-by-name slugs at lines 14 (Purpose enumeration, being rewritten anyway) and 46 (step 2 dispatch, unchanged); repo-wide grep finds **no** path string containing `mimir-codebase-context` anywhere (only its own frontmatter and README lines 131/179); `setup.sh` copies whole directories and the capability generator derives roles from slug prefixes (C-11). Registration and path updates: `setup.sh:167` and `validate.sh:762` lists gain `architecture`; `setup.sh` removes the four relocated slugs (incl. the old template name) from a deployed `engineering/` if present; `LICENSES/CC-BY-SA-4.0-arc42.txt` lines 6, 8, 66 name the new slug/path; comments/warnings and README follow (§5.1.10, §5.1.9). The moves are behavior-neutral by construction and execute first, as the scaffold package, so `validate.sh` is green before any content edit begins (Q-10).

## Consequences
- **Positive:** the reuse/decoupling principle is visible in the tree; a future consumer of architecture doctrine has one directory to depend on; Check 9 keeps enforcing that mandatory skills reference only mandatory skills across the new boundary; `engineering/` shrinks to four engineering-specific skills.
- **Negative:** two `MANDATORY_SKILL_DIRS` edits that must stay in sync (accepted — user-directed); a one-time upgrade hazard for existing installs, mitigated by the `setup.sh` cleanup of four slugs (R-9); README layout churn; the engineering workflow's context gate now depends on a skill that ships in another feature directory — harmless on any install because both directories are mandatory.
- **Becomes harder:** nothing material; a future move is the same recipe (§8.6).
