# ADR-0010: Dedicated `heimdall-architecture-review` skill owning the scaffold, document (both modes), and persistence checklists; `Focus: architecture` removed from `heimdall-engineering-review`

- **Status:** Accepted
- **Date:** 2026-09-18
- **Revision:** 2026-09-18 — the original recommendation (option A, a `Mode:`-aware `Focus: architecture` inside `heimdall-engineering-review`) was overridden by user direction at the plan checkpoint: architecture review must not share a skill file with the unrelated context/package/integration checklists. Amended in place (never persisted); option A retained below, marked **Rejected (user-directed)**.

## Context
The current `Focus: architecture` checklist (`heimdall-engineering-review/SKILL.md` lines 81–95) BLOCKs on missing packages/traceability and single-option decisions — inapplicable in document-existing mode (falsifies requirements assumption A-4). The same skill's `Focus: integration` carries the persisted-architecture checks (lines 125–136) because the engineering integration session is the one that persists. With ADR-0005 the engineering workflow no longer dispatches an architecture review itself; the Architecture workflow does, in both standalone and composite runs. A standalone run also needs a review of its persistence session, for which `Focus: integration` (full-suite-green first) is the wrong shape. Goals: Doctrine Minimization, Reusability, Backward Compatibility, Clarity of Intent.

## Options Considered
| Option | Pros | Cons | Doctrine Min. | Reusability | Backward Compat. | Clarity |
| --- | --- | --- | --- | --- | --- | --- |
| A. Keep `Focus: architecture` in `heimdall-engineering-review`; `Mode:` selects a document-mode subset — **Rejected (user-directed)** | Smallest edit; one skill | Architecture checklists stay coupled to the engineering-review file; standalone persistence review has no proper Focus | 0 | − | + | + |
| B. New `heimdall-architecture-review` with `Focus: document` (+ `Mode:`) and `Focus: persistence`; **delete** `Focus: architecture` from the engineering skill; its `Focus: integration` loads the new skill's persistence checklist by name | Every architecture checklist exists once, in the architecture family; engineering review keeps its dispatch count and checks; clear routing | New skill file; engineering-review edits in five places; a runtime skill-load inside a review | + | + | + | + |
| C. New skill for the document review only; leave the persisted-architecture items duplicated in `Focus: integration` and reuse `Focus: integration` for standalone persistence | No cross-skill load | Two copies of the persistence checklist drift; standalone runs are reviewed against a test-suite item that cannot apply | − | 0 | + | 0 |
| D. Deprecate `Focus: architecture` with a pointer instead of deleting it | Gentler for transcripts citing the old Focus | Two competing checklists for the same artifact type for an indefinite period — the exact anti-pattern; dead text in a mandatory skill | − | 0 | + | − |

## Decision
We use **B**. `skills/architecture/heimdall-architecture-review/SKILL.md` (new) accepts `Focus: document | persistence`; `Focus: document` also reads `Mode: decide-new | document-existing` (absent ⇒ decide-new) and applies the checklist moved verbatim from lines 81–95 for decide-new, or the document-mode subset in §5.1.5 for document-existing (BLOCKED additions: proposal language in §4/§9; §5 block without an evidence path; missing/mismatched `Mode:` header). `Focus: persistence` applies the items moved verbatim from lines 125–136 (merge-never-overwrite (a)–(f), decision promotion by ratification record, log↔file consistency, planning material transient), without a test-suite item. Verdict grammar: `Verdict: <…> — focus=<document|persistence>, mode=<…|n/a>, artifact=<path>, <reason>`. In `heimdall-engineering-review`, the `Focus: architecture` section and its Purpose-table row are **deleted** (not deprecated); a `Not for` line routes architecture artifacts to the new skill; `Focus: integration`'s persisted-architecture bullets collapse to one bullet that loads `heimdall-architecture-review` by name and applies its `Focus: persistence` checklist, "its blocking conditions blocking here". The Architecture workflow dispatches `Focus: document` at step 5 and `Focus: persistence` as the standing review of step 7. **Extension (Revision 2):** ADR-0011's scaffold step is a Brokk session and therefore carries a standing review (C-12); the skill gains a third value, `Focus: scaffold` (≤ 8 items, §5.1.5), dispatched at step 3 — keeping every architecture-artifact checklist in this one skill rather than reaching for `heimdall-engineering-review` or an optional skill (Check 9).

## Consequences
- **Positive:** the engineering-review skill shrinks to engineering-only artifacts; architecture review is reusable by any workflow; the persistence checklist has one home (Q-11); the earlier open issue about reviewing a standalone persistence session is resolved.
- **Negative:** one more mandatory skill file; the integration review performs a skill load at review time (R-11); `heimdall-engineering-review` is edited in five places, all deletions or one-line replacements.
- **Becomes harder:** reviewing an architecture artifact and an integration pass in a single Heimdall dispatch — they were already separate dispatches, so nothing is lost today.
