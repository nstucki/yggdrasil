# ADR-0010: Designer permission profile: workspace-markdown and image-file `edit` allowlist, unscoped read surface, no shell, no network

- **Status:** Accepted
- **Date:** 2026-09-20

## Context

The user fixed a minimal baseline (C13): write markdown within the Yggdrasil Workspace, write image files to any directory, read the Yggdrasil Workspace — with any further grant requiring a stated functional need. Authorization is the frontmatter permission block and nothing else (ADR-0003, C3); `edit` and `bash` take glob patterns, other tools take `allow`/`deny` (`agents/mimir.md:6-68`). Every peer that writes Workfiles has `edit` scoped to `.yggdrasil-workspace/**/*.md`; every peer has unscoped `read: allow`; Bragi — the closest peer, also without shell — has `glob`, `grep`, `read` and nothing else (`scripts/subagent-generator/bragi.template.md:6-18`). Whether OpenCode's `read` permission accepts path patterns is not evidenced in the repository. The `edit` tool writes text (C16), so the image globs make SVG authorable now and make raster paths *permitted* for a future granted tool without widening anything else. Standing goal S2 (least privilege) and revision goals **Consistency** (peer-shaped block) and **Clarity** (explicit, stated boundaries) are the forces; **Configurability** is neutral here.

**Stated needs for the three grants beyond the literal baseline (C13):** `read` unscoped — a designer must read the reference assets, style guides, and existing images the brief points to in the project, and must re-read the file he wrote to confirm it exists and parses; `glob` — locate existing assets and style guides by pattern (`**/*.svg`, `**/brand/**`) when the brief names a directory rather than a file; `grep` — locate design tokens (hex colors, font names) in stylesheets and theme files to honor "match the project's palette". None widens any write.

## Decision

We use **Option A**: the frontmatter fixed in §5.1.2. The `edit` block opens with `"*": deny`, allows the two workspace-markdown globs every Workfile author has, allows the six image-format globs anywhere in the project, and denies `.yggdrasil-memory/**` and `**/.yggdrasil-memory/**` explicitly; `glob`, `grep`, and `read` are `allow`; `skill` allows `eitri-*` only; `todo` is allowed; there is no `bash`, `webfetch`, `websearch`, or `lsp` key. Raster output is not attempted through `edit`; it awaits a post-install tool grant registered per `README.md:310-340`, whose own tool key the operator adds to the installed `eitri.md`.

Rationale: A is the peer-consistent block (Bragi's read surface) that adds exactly the write surface the user named, with each of the three read-side additions justified by a concrete design task rather than by convenience — which is what C13 requires. B is the letter of the constraint at the cost of a designer who cannot see what he is asked to match, on top of an unverified `read`-pattern semantics that could fail open. C adds channels for which no generation need exists.

**Amendment — 2026-09-21, post-implementation, user-directed (commits `793a5ca`, `755d6bb` on `feature/designer`; user confirmation: "Keep all of it as is.").** The two explicit deny globs `.yggdrasil-memory/**` and `**/.yggdrasil-memory/**` are **removed** from Eitri's `edit` block. Live state spot-checked: `scripts/subagent-generator/eitri.template.md:8-17` carries `"*": deny`, the two workspace-markdown allows, and the six image-extension allows — nothing else; `agents/eitri.md` is byte-identical to the regenerated output (commit `755d6bb`). The shared `memory.fragment.md` is prose only (no `permission:` content) and confers no host-enforced protection.

*Peer-pattern finding (spot check requested at amendment time).* **No agent in the repository carries an explicit Memory-path deny glob** — repo-wide search for `yggdrasil-memory/**` or any `deny` paired with `.yggdrasil-memory` across `agents/*.md` and `scripts/subagent-generator/*.md` returns zero hits. The four Workfile-writing peers (Mimir `agents/mimir.md:55-58`, Heimdall, Bragi `bragi.template.md:8-11`, Kvasir) protect Memory **by construction**: `edit` opens `"*": deny` and allows only `.yggdrasil-workspace/**/*.md` / `**/.yggdrasil-workspace/**/*.md`, which cannot match any path under `.yggdrasil-memory/`. Brokk (`agents/brokk.md:53-56`) has `"*": allow` with only the *workspace* denied, so Brokk's Memory boundary is **prose-only** (`agents/brokk.md:91`) plus the reviewed-pipeline governance of ADR-0008. Every agent additionally carries the prose bullet "Yggdrasil Memory … is read-only during your work — you never write to it" (`eitri.md:51`, `mimir.md:91`, `bragi.md:42`, `kvasir.md:81`, `heimdall.md:99`). **Consequence for consistency:** the explicit deny globs this ADR originally ratified were an *addition* to the pantheon's pattern, not a mirror of it; their removal makes Eitri's block **consistent with the peers**, and R17 (precedence reliance) is moot. The "defense-in-depth relative to the pattern ratified for other Workfile-writing agents" that the amendment request feared losing did not exist for those agents either.

*Residual gap, stated precisely.* Eitri's remaining allow globs do **not** match Memory *entries* — `.yggdrasil-memory/**/*.md` and `INDEX.md` are markdown and no `*.md` allow reaches outside the workspace — so there is **no functional write-access gap to Memory content today**. However, unlike the four markdown-only peers, Eitri's `**/*.svg|png|jpg|jpeg|webp|gif` globs **do** match a hypothetical `.yggdrasil-memory/<anything>.png`: Eitri could place a stray image file inside the Memory directory. It could not create, modify, or delete a Memory entry or the index. This is a tidiness exposure, not a governance breach (ADR-0008's pipelines govern entries, not arbitrary files), and it is guarded by the prose boundary and Heimdall review. It is the one respect in which Eitri's residual is wider than Mimir/Bragi/Kvasir/Heimdall's and narrower than Brokk's. Accepted by explicit user decision (R21).

## Consequences

- **Positive:** Eitri is functional on day one for vector assets with no external dependency; the block is explainable line by line in the README (**Clarity**); Heimdall can review the same files through the same `read` tool. *(Amended)* Eitri's `edit` block now follows exactly the pattern of every Workfile-writing peer — `"*": deny` plus narrow allows, no path-specific denies — so there is no Eitri-only permission idiom to explain (**Consistency**); the same `edit` block is now a template a seventh specialist can copy without inheriting an idiosyncratic deny (**Maintainability**).
- **Negative:** `**/*.png`-style globs permit overwriting any existing project image — this is what "write image files to any directory" means, but a brief that names an existing asset path replaces it; `read` exceeds the literal baseline (R15). *(Amended)* Memory protection for Eitri is by construction plus prose, not by explicit deny: a future widening of an `edit` allow glob (e.g. adding `**/*.md` for image-adjacent docs) would silently open Memory entries to Eitri with no deny to catch it — the same latent hazard every markdown-writing peer already carries; and Eitri alone among the markdown-only peers can drop a stray image file inside `.yggdrasil-memory/`.
- **Becomes harder:** narrowing later — once users rely on Eitri reading brand assets, restricting `read` to the workspace breaks briefs; adding a raster tool requires the operator to edit the installed `eitri.md` (volatile across upgrades, like every custom tool grant in this framework — `README.md:312-318`). *(Amended)* introducing explicit Memory denies later as a pantheon-wide convention — the precedent of "the designer is the one with denies" is gone, so it would have to be adopted for all six at once or not at all.
- **Risks and mitigations:** R15 → ratifier may choose B; the record shows what is lost. R17 → **moot** after the amendment (no deny-after-allow ordering remains in Eitri's block). Overwrite risk → Eitri's Boundaries require a `revision of` field in the brief before writing to an existing path, else `Image: blocked — asset path exists and brief does not mark a revision` (prose-enforced; reviewed by Heimdall). R21 (glob-widening hazard, stray-image exposure) → accepted by the user; QS-18's measure is revised to the amended block.
